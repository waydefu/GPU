## Remaining design findings

### HIGH — OOM can PASS without proving the injected branch ran

`judge-r6-design.py` accepts this shape:

```text
PRESENT_CALLBACK
COMPLETED cover
later Composite REQUEST
```

with the OOM env present. That same shape can come from the ordinary successful
requeue/poll path. Environment presence proves configuration, not consumption of
the post-schedule requeue-fail hook.

A host synthetic case containing no requeue-failure or ACK marker was accepted
as `R6_D2_PASS d2-oom`.

Required correction:

- Add a positive `PRESENT_REQUEUE_FAILED` marker tied to generation and GPU
  serial S.
- Keep historical event 32 as forbidden `PRESENT_EARLY_ACK`; do not repurpose it
  silently.
- Add a negative test where env=1 but the requeue-failure marker is absent.

### HIGH — ACK/idle ordering is claimed but not observable

The HOLD document requires:

```text
COMPLETED cover < ACK / idle < later request
```

The current judge checks only:

```text
COMPLETED cover < later request
```

It cannot distinguish “wait succeeded, then ACK” from “normal path completed”
or from a future implementation that forgets ACK entirely.

Required correction:

- Add `PRESENT_ACK_AFTER_COMPLETED` after `lorieGpuCopyAck` returns.
- Static verification must prove wait-or-fatal precedes Ack, and Ack precedes
  this marker/idle path.
- Runtime judge requires ACK marker after both the requeue-failure marker and
  completion cover, then the later request.

Completion may happen before the requeue failure is detected on a fast renderer.
Therefore do not require `REQUEUE_FAILED < COMPLETED`; require both after the
Present callback and require ACK after both.

### HIGH — OOM does not require later direct SUCCESS

The session summary says later direct SUCCESS is mandatory, but the current code
requires it only for D2-INFLIGHT. D2-OOM passes after any later Composite request,
even if it falls back to software or never reaches a direct terminal.

Required correction:

- D2-OOM must require later target Composite CALLBACK and same-generation direct
  SUCCESS after the ACK marker.
- Keep exact pixels as a separate correctness oracle; do not use them as direct
  path identity.

### MEDIUM — D2 SUCCESS is not bound to the target buffer pair

D2-INFLIGHT currently accepts any same-generation SUCCESS with `serial > S`.
A SUCCESS for another destination can close the cell. A synthetic SUCCESS with a
destination different from the reason-1 reject was accepted.

Required correction:

- Pair Present REQUEST and CALLBACK by client sequence.
- Bind reject destination ID to later direct lease/publish/SUCCESS destination.
- Match source ID too when the fixture keeps the same source.
- Add wrong-client and wrong-destination negative tests.

### MEDIUM — missing sequence prefix is not treated as a gap

The judge checks contiguity only from the minimum captured sequence to the
maximum. A fresh trace containing only `seq=10..16` passes even though `0..9` are
missing. A host synthetic case confirmed this.

For a fresh non-overflowed R6 process, sequence starts at zero. Required
correction:

- Require range `0..max_seq` after follow/ring merge.
- Keep `max_seq >= capacity` as overflow FAIL.
- Add missing-prefix and ring-filled-prefix tests.

### MEDIUM — runtime directory and version are not cryptographically bound

The shell case pattern `runtime-[0-9a-f]*` means one hex character followed by
anything. It accepted `runtime-aNOTHEX`. It also accepted
`runtime-54ff35b` with an `EXPECT_VERSION` embedding `deadbee`.

Required correction:

- Parse an anchored `runtime-[0-9a-f]{7,40}` basename.
- Require its short SHA to equal the SHA embedded in `EXPECT_VERSION`.
- Restrict cells to the canonical runtime evidence root.
- Add malformed-hex, wrong-length, and SHA/version mismatch negative tests.
- Preserve APK hash/Build ID/live mapped APK binding through the existing
  artifact/device qualification chain.

### MEDIUM — cross-file wait/fail-stop API is not frozen

`lorieGpuCopyWait` is currently `static` in `InitOutput.c`; it cannot be called
directly from `present_execute.c`. The design names the wait but does not freeze
the translation-unit interface or exact fatal reason.

Recommended narrow contract:

```text
InitOutput.c:
  exported lorieGpuCopyWaitForPresentOrFatal(serial)
  internally calls the existing bounded wait
  returns only after completedSerial >= serial
  timeout/renderer loss publishes generation fatal and halts

present_priv.h:
  declares only the wait-or-fatal wrapper

present_execute.c requeue-fail branch:
  trace REQUEUE_FAILED
  call wait-or-fatal wrapper
  Ack/decrement/release
  trace ACK_AFTER_COMPLETED
  pixmap idle / ordinary completion
```

Do not expose a raw Boolean wait that lets callers ignore failure and release
ownership anyway. Freeze the fatal reason and diagnostic string before coding.

## Corrected OOM oracle

Let `S` and `G` come from the target Present callback. Let `T` be a renderer
completion watermark.

```text
PRESENT REQUEST(clientSeq=C)
  < PRESENT CALLBACK(clientSeq=C, generation=G, serial=S)

PRESENT CALLBACK < PRESENT_REQUEUE_FAILED(G,S)
PRESENT CALLBACK < COMPLETED(role=RENDERER, generation=G, serial=T>=S)
max(REQUEUE_FAILED, COMPLETED) < PRESENT_ACK_AFTER_COMPLETED(G,S)
ACK_AFTER_COMPLETED < later target Composite REQUEST/CALLBACK
later target direct SUCCESS generation=G, serial>S, matching destination
```

Forbidden anywhere in the OOM target interval:

```text
PRESENT_EARLY_ACK
ACK/pending--/ref release before completion
normal fallback after timeout or renderer loss
X-client dispatch from inside the terminal wait
```
