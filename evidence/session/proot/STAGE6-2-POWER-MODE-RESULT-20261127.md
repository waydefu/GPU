# Stage 6.2 電源模式對照 — 實測結果報告（2026-11-27）

> **凍結規則依據**：[`STAGE6-2-POWER-MODE-FREEZE-20261127.md`](STAGE6-2-POWER-MODE-FREEZE-20261127.md)（已凍結，本文件為獨立結果報告，未回改凍結文件）。

## 1. 摘要與結論

- **執行範圍**：依授權執行第一輪 ABBA（`B1 P1 P2 B2`）及紅色對照（`S1`），共 **5 個 180 秒有效區塊**（合計 `370/370` 複合批次零失敗、`orphan_pids=0`、`adb_fail_ratio=0.0`、`termux_kills=[]`）。第一輪結束後因發現確定結論與數學鎖定條件，經使用者確認採選項 A 提前收斂，略過第二輪重複（`B3 P3 P4 B4`）。
- **工具正式判決**：`INVALID`（因未執行 `B3–B4`，且第一輪 `P1=2176.64 ms` 與 `P2=2325.60 ms` 已造成 `performance` 同模式離散達 **`6.617%`**，無論第二輪測出何值，V7 離散 `(max-min)/median` 恆 **`≥ 6.405% > 4.0%`**）。
- **實質工程結論（Stage 6 計畫書 §4.1 候選 3）**：**不採納「效能模式」作為裸機日常長穩態模式（相當於 `PAUSE`／僅限短時爆發）**。
  - **短時爆發（0–30 秒）確實快 ~6.4%**：`B1→P1` `+6.39%`、`B2→P2` `+6.45%`。
  - **裸機長穩態（90–180 秒）撞溫控牆且超溫**：兩次 `performance` 皆突破 G4 上限 `85.0 °C`（`P1` 達 **`87.2 °C`**、`P2` 達 **`85.7 °C`**）；且起測電池僅 `33.1 °C` 的 `P2` 在後段遭 HyperOS 主動把 `cpu6` 頻率上限砍半至 **`2,227,200 kHz`**（低於均衡模式 `2,880,000 kHz`），導致效益歸零（`-0.00%`、`late/early=1.069`）。
  - **均衡模式基線極穩**：`B1`（`2324.89 ms`）與 `B2`（`2325.50 ms`）僅差 **`0.026%`**，無熱降頻反超，維持日常預設。
  - **紅色對照通過 V8**：省電模式 `S1`（`2529.36 ms`）較均衡中位數（`2325.19 ms`）慢 **`+8.78%`**（遠高於 `2.0%` 門檻），證實量測工具對差異具足夠靈敏度。

## 2. 工具驗證與修正紀錄（依凍結文件 §7）

工具實作位於 `scripts/stage6_2_judge.py`、`scripts/stage6_2_power_bench.py` 與 `scripts/test_stage6_2_judge.py`。

1. **合成測試（13/13 PASS）**：涵蓋明確勝出 → `GO`、無差異 / 單對倒退 ≤ -2% / G5 殺程 → `RETIRE`、early 勝但 late 崩 / G1/G3/G4/G6 失敗 → `PAUSE`、同模式離散 > 4% / 紅對照 < 2% / cherry-pick attempt 2 / `null` 欄位 → `INVALID`。
2. **修正紀錄（不抹除錯誤版本）**：
   - 修正 `judge_series` 中 `P2-B2` 與 `P4-B4` 配對欄位順序反轉導致符號顛倒的 bug（最初單元測試即攔截失敗 5 項，修正後全過）。
   - 30 秒乾跑（`DRYRUN_attempt1.json`：`dur=32.28s`、13/13 批、`samples=6`、`orphan_pids=0`）發現 `dumpsys battery` 中 `Max charging voltage: 0` 排在 `voltage: 4111` 之前，使無行首錨定的 regex 誤讀為 `0`；已改為行首錨定 `parse_battery_fields` 並補回歸測試。
   - 乾跑實測 `Charge counter` 序列 `[4642000, 4626000, 4626000, 4626000, 4626000, 4626000, 4611000, 4611000]` µAh，單次跳動步階為 **15,000–16,000 µAh**（32.28 秒共耗 `31,000` µAh）；據此將 5× 解析度門檻設為 `5 × 16,000 = 80,000` µAh（乾跑記 `null`，180 秒區塊實測多數達標）。

## 5. 最終建議與限制

- **建議**：維持 **`balanced`（均衡模式）** 作為日常工作站預設；僅在**短時間（約 30–60 秒內）編譯或高互動需求，或有外接主動散熱器**時，由使用者手動切換至 `performance`。
- **限制**：結論僅適用本機（POCO F8 Ultra `myron`）、本工作站複合負載、裸機電池放電（`status: 3`、`77%–79%`）狀態；未測第二輪 `B3 P3 P4 B4`（因 V7 離散鎖定 >4% 且 G4 已於 `P1`/`P2` 失敗）；`PSI` 與 `zram0/mm_stat` 因非 Root 權限不足不可取得；去敏後逐批原始 JSON 與 SHA256 清單存於 [`stage6-2-runs-20261127/`](stage6-2-runs-20261127/README.md)（本機完整原始檔於 `/data/data/com.termux/files/home/build/proot-fast/stage6_2_runs/`）。
