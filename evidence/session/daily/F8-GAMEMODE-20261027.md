## 發現：偵錯從來沒有被關掉

手機端 log（`/data/local/tmp/f8-gamemode-phone.log`，10-03 15:35 的實際執行）：
三個 `am force-stop` rc=0，但 `settings put global adb_wifi_enabled 0` 和 `adb_enabled 0` **都是 rc=255**。

原因已逐項排除並證實（輸出見 `device-probes.txt`）：
| 檢查 | 結果 | 結論 |
|---|---|---|
| 背景 shell（`setsid nohup sh -c`）裡讀 settings | rc=0 | 不是背景執行環境的問題 |
| `com.android.shell` 的 `WRITE_SECURE_SETTINGS` | `granted=true` | 不是 Android 權限沒給 |
| `persist.security.adbinput` | `0` | MIUI「USB 偵錯（安全設定）」關著 |
| 把無害 key `stay_on_while_plugged_in` 用原值寫回 | `SecurityException: Permission denial` | **MIUI 在安全設定關閉時擋下 shell 的所有 settings 寫入** |

10-03 的真機驗證把 `settings put` 換成 `echo`（`handoff-harmless.txt`），所以沒有測到這個限制；
腳本也從不讀 rc，使用者只看到「2 秒後關閉 Termux 與偵錯」。實際效果：只有 Termux 被關，USB／無線偵錯一直開著。

另一個問題（今天實際遇到）：配對過期時 `f8-adb-port` 仍會回報埠（46691 有回 adb 協定），
但 `connect` 失敗，之後 `dumpsys input` 失敗，提示誤報「讀不到輸入裝置」並整個中止。

## 修正（備份：`/data/data/com.termux/files/usr/bin/f8-gamemode.bak-20261027-precheck`）

1. 找到埠之後用 `adb get-state` 確認是 `device`；不是就走手動分支，原因寫「adb 連不上（配對可能過期）」。
2. 交給手機之前先做寫入預檢：`adb_wifi_enabled` 為 1 時寫回 1（值不變，系統不觸發任何反應），只看結束碼；
   失敗就走手動分支，原因寫「系統不准 adb 改設定（MIUI「USB 偵錯（安全設定）」沒開）」。
3. 手動分支提示一律寫明「偵錯沒有關」與原因；adb 沒連上（無法檢查外接裝置）時再加「拔掉外接滑鼠／鍵盤」。
4. 預檢通過時的交接流程不變。

**實機確認新腳本依賴的行為**：`get-state` = `device`；`adb shell false` 回 1（遠端結束碼會傳回）；
預檢指令 rc=255（目前會正確走手動分支）；預檢後 `adb_wifi_enabled` 仍為 1。
