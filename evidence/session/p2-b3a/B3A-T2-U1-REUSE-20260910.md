# B3a Tier-2 U1 reuse 系列 — 2026-09-10（回答攤銷假說）

問題：同一 pixmap 重複 reuse，R3 的 clone/prepare 能否被攤平？
設計：64 reuse{1,4,16,64}＋256 reuse{1,64}，warmup 100＋measured 500，
warm reuse＋immediate GetImage，batch=1 cold=0；CPU/R3 各一 session，
holder＋oracle＋批量＋釋放 dump，exact-count 5119/5119 兩邊通過，
teardown 乾淨，Stable 未碰。

## Wall medians（毫秒）

| cell | cpu | r3 | r3/cpu |
|---|---|---|---|
| 64r1 | 2.175 | 2.818 | 1.30 |
| 64r4 | 2.149 | 2.820 | 1.31 |
| 64r16 | 2.200 | 2.838 | 1.29 |
| 64r64 | 2.224 | 2.876 | 1.29 |
| 256r1 | 2.284 | 4.517 | 1.98 |
| 256r64 | 2.315 | 4.704 | 2.03 |

## 結論

1. reuse 不攤銷：64 在 reuse 1→64 完全平坦（2.818→2.876），256 亦然
   （r64 反而微升）。measured 窗口內 promotion 全 null（warmup 已攤銷首輪），
   剩下 prepare+clone+done 是每 composite 固定復發成本。persistent residency
   不能降低 per-op 成本——Gate D 方向在此數據下不支持。
2. 256 回歸持續且更重：1.98～2.03x（Tier-1 為 1.51x）；prepare 0.70、
   clone 0.45、done 0.89，隨 source footprint 放大。
3. 方法學警訊（誠實記錄）：同參數 CPU-64 在 Tier-1 為 2.930、本輪為 2.175，
   跨 session 漂移約 25%；R3-64 兩輪為 2.741 vs 2.818（穩定）。
   跨 session 絕對值比較有噪聲，同一 session 內的相對形狀（平坦/回歸）才可靠。
   後續比較以同輪配對為準。
